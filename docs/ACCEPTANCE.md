## 사용자 Linux 서버에서 반드시 실행할 검사 — 미실행

### 설치·SDK

- [ ] 비-root 사용자, Node 24, npm, Git을 준비한다.
- [ ] `bash scripts/install.sh`가 끝까지 성공한다.
- [ ] `npm run typecheck`가 **설치된 실제 @getpaseo/plugin**에 대해 성공한다.
- [ ] `node engine/bin/paseodog-engine.mjs --check`가 성공한다.
- [ ] `paseodog plugin ls`와 앱에서 PaseoDog provider가 보인다.
- [ ] 초기 프로필이 다른 앱의 인증·설정을 덮어쓰지 않았음을 확인한다.

### 실제 엔진·권한

- [ ] `paseodog auth`로 전용 프로필 인증을 완료한다.
- [ ] `node scripts/live-smoke.mjs --confirm-api-use`의 두 요청과 복원이 성공한다.
- [ ] 테스트 저장소에서 파일 읽기 요청을 허용하고 결과를 확인한다.
- [ ] 파일 수정 요청을 **거절**한 경우 파일 해시가 바뀌지 않는다.
- [ ] 같은 요청을 새 작업으로 보낸 뒤 1회 허용하면 의도한 변경만 발생한다.
- [ ] shell 승인에 전체 명령이 표시되며, 거절하면 실행되지 않는다.
- [ ] 실제 native 도구에서 승인 만료·작업 중단 뒤 늦은 허용이 실행을 재개하지 않는다.
- [ ] MCP stdio 및 HTTP/SSE가 필요한 환경에서는 각각 연결·승인·거절을 검증한다.
- [ ] `/compact` 이후 제약과 최근 요구사항이 유지되는지 실제 장기 대화로 확인한다.

### 휴대폰·SSH

- [ ] 기존 Paseo 앱에서 서버 호스트에 연결한다.
- [ ] 같은 agent-id가 SSH와 휴대폰에서 보인다.
- [ ] Wi-Fi를 끄고 LTE/5G에서 스트리밍·승인·중단을 확인한다.
- [ ] 앱을 닫았다 다시 열어도 동일 요청이 두 번 실행되지 않는다.
- [ ] 휴대폰이 백그라운드에 있을 때 승인 요청을 놓친 경우 만료 후 거절된다.
- [ ] 터미널 attach 종료가 서버 작업 종료와 혼동되지 않는지 확인한다.

### 장애·재부팅

- [ ] 입력을 보낸 직후 네트워크를 끊었다 복구해 중복 실행 여부를 확인한다.
- [ ] 테스트 작업 중 엔진 프로세스를 종료하고 실패가 표시되는지 확인한다.
- [ ] 데몬 강제 종료 뒤 해당 요청이 자동 재실행되지 않는지 확인한다.
- [ ] 재부팅 뒤 systemd 사용자 서비스·인증 접근·세션 복원이 정상이다.
- [ ] 이미 수행한 파일 수정이나 외부 요청이 자동 롤백되지 않는다는 점을 운영자가 이해한다.

### 토큰 비교

- [ ] 동일 모델·effort·작업·성공 기준으로 기존 에이전트와 비교한다.
- [ ] input에 cached tokens가 포함된 측정 체계를 맞추고 중복 합산하지 않는다.
- [ ] 압축용 추가 모델 호출·재시도·실패 작업의 토큰도 포함한다.
- [ ] 토큰 절약률과 비용 절감률을 별도로 보고한다.

## 출시 판정

현재 판정은 **RC / 실제 배포 수용 검사 미완료**입니다. 위 실제 설치·모델·권한·휴대폰·재부팅 검사가 통과한 환경에 대해서만 운영 가능 판정을 내립니다. 자체 브랜드 APK/IPA 및 상위 앱의 모든 기능 호환은 이 ZIP의 완료 범위가 아닙니다.
