# PaseoDog rc.3 preflight remediation (2026-10-12)

## Scope

Addresses four regressions found during the rc.2-hotfix readiness audit, plus
non-reproducible transitive dependency resolution. Commits must be verified by
GitHub CI on Node 24 before declaring the SDK/native installation checks pass.

1. **State safety:** `tests/preflight-regressions.test.mjs` packages a temporary
   copy of MANIFEST-reviewed source and keeps fake credentials inside that copy.
   It never creates or deletes `<checkout>/state`. An existing canary is
   preserved across `npm test`.
2. **Worker death:** `process-engine.mjs` handles `exit` separately from
   `close`, failing pending RPCs immediately even when another process inherited
   stdout. Exit and cleanup are deduplicated. Fixture
   `tests/fixtures/exit-pipe-worker.mjs` reproduces the pipe-retention race.
3. **Linux native subprocesses:** Production defaults to dedicated systemd
   **user scopes**, which are cgroups independent of native process group IDs.
   The bridge stops/kills the systemd unit and checks `cgroup.events`
   population. If there is no systemd user bus, the engine fails *before*
   spawning the unsupervised worker. `test-only-process-group` exists solely
   for OS-level fixtures. A live, real-systemd Mixdog shell/grandchild test
   remains required on the deployment server; CI checks mocked scope contracts.
4. **Paseo display:** Mixdog text reset acknowledgements are always rejected
   until the client protocol supports deletion. Assistant snapshots emitted to
   Paseo cannot shrink or diverge from the previously visible prefix. Some
   corrective provider responses therefore remain visible as partial stream;
   the bridge emits a notice rather than silently duplicating text.
5. **Supply chain:** All three npm `package-lock.json` artifacts previously
   generated by successful GitHub CI were incorporated and updated to rc.3
   top-level metadata. Install and GitHub CI use `npm ci` only. The ZIP
   manifest includes lockfiles. Native Mixdog requires `--install-strategy=nested`.

## Safety model and production limitations

- Linux `systemd --user` manager is now a prerequisite for the native bridge.
  A rootless container without it is deliberately unsupported. Cgroup scope
  lifecycle must be validated on the actual server; the CI runner does not
  expose a persistent user systemd manager for this integration test.
- Any approved shell/MCP code still runs with the dedicated Unix user's
  privileges. Cgroups manage lifetime, not sandboxed filesystem/network access.
- Native runtime, model authentication, private relay, mobile reconnect,
  user-session reboot and actual native shell grandchild cleanup are not
  validated by the local mock suite. Do not mark the project production-ready
  solely because unit, typecheck and install checks pass.
- The base `reports/VERIFICATION.md` and `reports/PREFLIGHT-FIXES.md` document
  older candidates, not the final rc.3 live acceptance state.
